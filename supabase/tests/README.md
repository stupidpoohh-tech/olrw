# 스키마 검증

Supabase 프로젝트도 Docker도 필요 없다. 로컬 Postgres 바이너리(15+)만 있으면 된다.

```bash
supabase/tests/run.sh              # RLS · 서버 함수 45케이스
supabase/tests/concurrency_test.sh # 동시 마감 5케이스
```

일회용 클러스터를 띄워 `harness.sql`(auth/storage 스텁) → `0001_init.sql` 순으로 올리고
검증한 뒤 지운다. 이미 도는 서버가 있으면 `PGHOST=... PGPORT=... run.sh`.

## 무엇을 지키고 있나

각 케이스는 `docs/AUDIT.md`의 결함 번호(S…)나 `docs/decisions.md`의 결정 번호(D…)와 연결된다.

| 묶음 | 지키는 것 |
|---|---|
| 침입 차단 | box_id를 알아도 남의 전보함에 들어갈 수 없다 (S2) |
| 타전 | 남의 이름으로 못 쓰고, 쓴 뒤엔 못 고치고, 다른 권으로 못 옮긴다 (S5) |
| 봉인 | 남의 이번 권 전보는 행 자체가 안 보이고, 봉투만 분량을 알려준다 (D1) |
| 함께 읽기 | `begin_reading`으로만 열리고, 열리면 전원에게 열린다 (D2·D4) |
| 제본 | 위조 불가, 스냅샷 고정, 0건 마감 차단, 다음 권 재봉인 (S3) |
| 소프트 삭제 | 회수는 되지만 되살리기는 안 되고, 디스크에는 남는다 (S9) |
| 소유자 이양 | 방장이 나가도 전보함이 잠기지 않는다 (S8) |
| 동시 마감 | 둘이 같이 눌러도 권은 하나, 전보는 유실되지 않는다 |

## 주의

`harness.sql`은 **로컬 검증 전용**이다. 실제 Supabase에 적용하지 않는다 —
`auth`·`storage` 스키마는 이미 존재하고, 덮어쓰면 프로젝트가 망가진다.
