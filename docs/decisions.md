### D3·D5 미채택에 따른 스키마 처리

- `telegrams.retracted_at` — 만들지 않는다. `deleted_at`으로 충분하고, D5 미채택이므로 회수 개념 자체가 없다.
- `meetings` 테이블 — 만들지 않는다.

## D9 — 타자기: 색이 아니라 물건 네 대 (확정)

단계 2에서 발견. 번들 사진이 이미 무채색이라 §4-2 의 filter 여덟 개가 전부 같은 회색을 냈다
(가장 가까운 쌍 ΔE 1.0). 전보함을 색으로 구분한다는 장치가 동작하지 않았다.
근거는 `docs/AUDIT.md` §04-5.

**결정: CSS 필터를 버리고 색깔별 사진 여덟 장을 쓴다.** 원본이 있으므로 새로 제작해서 넣는다.

- `TypeColor.filter` 는 남기되 **폴백 전용**이다. 사진이 있으면 쓰이지 않는다.
- 사진 경로는 `public/assets/typewriter/{id}.webp`. 규격은 `docs/typewriter-photos.md`.
- 여덟 장이 다 들어오기 전까지는 기존 단일 사진 + 필터로 폴백한다 — 화면이 깨지지 않는다.
- 검사: `pnpm tint:check` (색 간 ΔE 8 이상)

`tint` 대표색 8종은 그대로다. 바뀐 것은 그 색에 도달하는 방법뿐이다.

## 단계 4에서 확인된 것

- **제본된 권은 지울 수 없다.** `volumes` 에 멤버용 delete/update 정책이 없고 권한도 회수돼

  하드 삭제가 있었지만 옮기지 않았다 — 스펙 §1 원칙 4("제본된 권은 삭제가 쉬우면 안 된다")와

- **전보 회수는 남긴다.** 작성자만, 소프트 삭제로. 되살리기는 서버가 막는다.
- **키 자리는 사진에 묶여 있다.** `src/features/transmit/keys.ts` 가 사진 기준 백분율로

  `pnpm ui:check4` 가 "A 를 누르면 A 키 자리에 온다"로 이걸 지킨다.

## 단계 5에서 정한 것

- **제본은 애니메이션과 나란히 돈다.** 참조 구현은 5.8초가 끝난 뒤에 `closeVol` 을 불렀다.
  서버가 느리거나 실패하면 사용자가 5.8초를 기다린 뒤 다시 기다리게 된다.
  지금은 `binding` 진입과 동시에 `close_volume` 을 부르고, 애니메이션이 끝날 때 결과를 기다린다.
  실패하면 표지 고르기로 돌려보내고 이유를 알린다.
- **표지 사진은 권보다 먼저 올라간다.** 권 id 를 알 수 없으므로 파일명은 uuid 로 짓는다
  (`covers/{box_id}/{uuid}.jpg`). `uploadCover(boxId, file)` 가 경로를 돌려준다.
- **모션을 줄이는 설정에서는 타임라인 자체를 건너뛴다.** CSS 로 애니메이션만 꺼 두면
  5.8초 동안 빈 화면을 보게 된다. `useReducedMotion()` 이 0.4초 뒤 결과로 보낸다.
- **금박 각인의 글자는 흰색이다.** 금색은 표지 테두리가 낸다 — 참조 구현의 값이 그렇다.
  완료 화면의 책 라벨만 금색(`--gold-light`)이다.

## 단계 6에서 정한 것

- **합성 함수는 `BaseAudioContext` 를 받는다.** 재생은 `AudioContext`, 검증은
  `OfflineAudioContext` 로 **같은 코드**를 돌린다. 오디오는 조용히 망가진다 —
  노드 연결 하나가 빠져도 화면은 멀쩡하고 소리만 안 난다.
  `pnpm sound:check` 가 §6-1 이 지정한 주파수(2200/3300Hz, 80Hz, 180→60Hz 등)가
  실제로 나오는지 Goertzel 로 잰다.
- **캐리지 쿵을 `setTimeout` 이 아니라 `t0 + 0.28` 로 예약한다.** 참조 구현은
  setTimeout 을 썼는데 탭이 바쁘면 밀린다. §6-1 의 "280ms 뒤"는 벽시계가 아니라
  소리의 시각이다.

### 남겨 둔 것 — 음소거

지금은 소리를 끌 방법이 없다. 참조 구현에도 없었고, 포팅 중 기능을 더하지 않는다는
원칙에 따라 넣지 않았다. 다만 타건음은 글자마다 울리므로 공공장소에서는 부담스럽다.
**7단계에서 다룰 후보다.** 넣는다면 전보함 설정이 아니라 기기 설정이어야 한다 —
소리는 개인의 상황이지 전보함의 성격이 아니다.

## D10 — 책등에 사진을 깔지 않는다 (확정)

사진 표지를 넣으면 책등이 대차게 잘렸다. 책등은 34×150px, 1:4.4 스트립이라
5:7 사진을 `cover` 로 깔면 가운데 세로 띠만 남는다. 게다가 금박 글자가 사진 위에서 묻히고,
긴 제목은 세로쓰기가 여러 열로 흩어졌다.

**결정: 책등은 사진의 대표색, 사진은 머리의 정사각 조각과 앞표지에서.**
실물 책의 논리 그대로다 — 책등에는 제목이 있고 사진은 앞표지에 있으며, 앞표지는 꺼내야 보인다.

- 대표색은 그릴 때 사진에서 계산한다(`coverTint.ts`). **스키마를 건드리지 않는다.**
  색상은 원형이라 벡터 합으로 내고, 명도를 24~36%로 눌러 금박 글자가 언제나 읽히게 한다.
- 책등 머리에 34×34 사진 조각. 실물 책의 레이블 자리다.
- 사진은 책을 펼치면 5:7 앞표지로 온전히 보인다.
- 제목은 `white-space: nowrap` + `text-overflow: ellipsis` 로 한 열 고정.
  `min-height: 0` 이 없으면 flex 가 눌러 한 글자만 남는다.
- 사진 위에 글자가 놓이는 곳(앞표지·완료 화면·제본 애니메이션)에 스크림을 넣었다.
  §4-3 이 요구한 것인데 빠져 있었다.

## D11 — ~~로그인 앞에 소개 화면~~ (D12 로 번복)

예전에는 로그인 화면이 먼저 섰다. 이 제품은 첫눈에 뭔지 알기 어렵다 —
전보함, 봉인, 제본, 서가. 계정을 만들기 전에 무엇인지 볼 수 있어야 한다.

- 로그인하지 않으면 `LandingScreen` 이 선다. 담는다 → 만나서 맺는다 → 아카이브,
  그리고 "이런 것은 없습니다".
- 설명 그림을 그리지 않는다. **앱에서 쓰는 그 컴포넌트**(`TelegramCard`, `SealedEnvelope`,
  책등)를 그대로 놓는다. 소개와 실물이 어긋날 수 없다.
- 해시로 상태를 남긴다(`#login` / `#join`). 화면이 하나 더 생긴 이상 뒤로 가기가
  소개로 돌아와야 한다. 로그인하고 나면 해시를 지운다.
- 로그아웃하면 로그인 화면이 아니라 소개로 돌아간다.


## D12 — 시작화면 없이 곧장 체험 모드 (확정 · D11 번복)

D11 은 소개 화면(LandingScreen)을 계정 화면 앞에 세워, 앱이 무엇인지 먼저 보여주려는
결정이었다. 그 뒤 D9(타자기 4대)를 채우고 안내 투어(GuestTour)를 만들면서 두 가지
사실이 분명해졌다.

- **투어가 소개를 이미 맡는다.** 온보딩 → 타전실 → 탭 → 만남 마감 4 스텝은
  랜딩의 세 절과 같은 것을 다룬다. 게다가 **실제 화면 위에서** 다룬다.
- **랜딩은 실물이 아니라 실물 조각이었다.** 카드와 봉투를 보여주지만 만질 수 없다.
  체험 모드 + 투어는 실제로 만질 수 있다 — "만나서 하고 싶은 말을 차곡차곡 담고,
  만나서 맺고, 아카이브한다" 를 진짜로 해 볼 수 있다.

그래서 랜딩을 없앤다.

- 미로그인 방문자는 곧장 체험 모드로 진입한다. `PublicGate` 가 방문 즉시
  `enterAsGuest()` 를 부른다.
- 로그인/가입은 게스트 배너의 링크(`#login` / `#join`)로 진입한다. AuthScreen 은
  유지되지만 앞 페이지가 아니라 옆 페이지다.
- 로그아웃하면 다시 게스트로 자동 진입한다. 로그인 화면이 다시 서지 않는다 —
  배너의 "로그인" 링크로 다시 들어간다.
- `src/features/landing/` 은 삭제한다.


## D13 — 인쇄물은 6px, 조작은 알약 (확정 · 절대 규칙 6 개정)

원래 규칙 6은 "반경 최대 6px, 둥근 카드 금지"였다. 인쇄물 은유를 지키려던 것인데,
그 결과 **버튼도 종이처럼 각져서** 무엇이 눌리는 것인지 눈으로 구분되지 않았다.

규칙을 반으로 가른다.

- **인쇄물** — 전보 용지, 봉투, 카드, 책 표지, 서가. 반경 최대 6px 그대로.
  종이는 모서리가 둥글지 않다. 이 은유는 유지한다.
- **조작** — 버튼, 칩, 세그먼트, 배지. `--radius-btn`(999px) 알약.
  누르는 것만 둥글다.

그래서 화면에서 **각진 것은 읽는 것, 둥근 것은 누르는 것**이 된다. 은유를 깨는 게
아니라 은유의 경계를 분명히 하는 쪽이다.

함께 바뀐 것:
- 봉인함/열린함이 알약 하나를 반으로 나눈 세그먼트가 되었다. 두 줄이다 —
  봉투 아이콘 + 이름 / 짧은 부제("지정한 날 함께 열어요" · "지금 바로 열 수 있어요").
  봉인은 덮개가 덮여 있고(안쪽 V), 열린함은 몸통 위가 트이고 덮개가 위로 솟는다.
  고른 쪽이 잉크로 채워지고, 자세한 설명은 알약 아래 한 줄로 남는다.
  **높이는 48px.** 처음 두 줄 판은 71px 로 두꺼웠는데, 부제를 지우는 대신
  줄 간격(gap 1px) · 행간(1.2/1.25) · 패딩(7/8px)을 조여 내용을 지키면서 얇게 눕혔다.
- 버튼 높이를 전반적으로 줄였다 (전보함 만들기 52 → 46, 만남 마감 49 → 43,
  송신 40 → 36). 두께가 얇아야 종이가 주인공으로 남는다.


## D14 — Supabase 에서 Neon 으로 (확정)

Supabase 무료 요금제는 조직당 프로젝트 두 개가 상한이다. 그 자리가 이미 다른
프로젝트 둘로 차 있어서 OLRW 가 들어갈 자리가 없었다. Neon 무료 요금제는 100개다.

**화면 코드는 한 줄도 바뀌지 않았다.** `interface BoxStore` 를 세워 둔 값을 여기서
받았다 — 갈아탄 것은 `src/lib/` 안의 구현체 하나다.

### 왜 갈아탈 수 있었나

Neon Data API 는 PostgREST 다. Supabase 의 질의 계층과 같은 물건이라
`from().select().eq()` 도 `rpc()` 도 그대로다. 인증은 `SupabaseAuthAdapter` 를
끼우면 `signUp` `signInWithPassword` `onAuthStateChange` 가 같은 이름으로 온다.

RLS 도 그대로다. `pg_session_jwt` 가 **`auth.uid()` 를 uuid 로** 준다 — Supabase 와
이름도 반환형도 같다. **정책 열다섯 곳을 한 글자도 고치지 않았다.**

### 바뀐 것 셋

1. **프로필을 만드는 문.** Supabase 에서는 `auth.users` 에 트리거를 걸었다.
   Neon Auth 의 사용자 표는 `neon_auth` 가 관리해서 트리거도 외래키도 걸 수 없다 —
   걸면 다음 업그레이드에서 깨진다. 대신 `ensure_profile()` 을 두고, 로그인 직후
   첫 조회에서 앱이 한 번 부른다. id 는 인자가 아니라 `auth.uid()` 라 남의 프로필을
   만들 수는 없다.

2. **체험 모드가 브라우저 안으로 들어왔다.** Supabase 의 익명 로그인은 진짜 사용자를
   하나 만들어 줬다. Neon 의 `anonymous` 역할에는 사용자 id 가 없어서 전보를 쓸 수도,
   전보함을 만들 수도 없다. 그래서 체험 모드는 서버에 닿지 않고 `memoryStore` 위에서만
   돈다 — `withGuestMode()` 가 "지금 누구인가"만 보고 두 구현 중 하나로 넘긴다.
   체험 데이터는 로그인하는 순간 지운다. 남기면 정식 계정 옆에 유령 전보함이 붙는다.

3. **표지 사진이 잠시 빠졌다.** Neon 에는 Storage 에 대응하는 것이 없다.
   Object Storage 는 베타이고 리전이 하나뿐이며, 브라우저에서 바로 올리려면
   presigned URL 을 발급할 서버가 필요한데 이 앱에는 서버 코드가 없다.
   `BoxStore.canUploadCover` 를 두고, false 면 제본 화면이 사진 버튼을 **아예 그리지
   않는다** — 누르면 실패하는 버튼을 두느니 없는 편이 낫다. 스키마의 `cover_kind` 는
   `'photo'` 를 그대로 받아 두었으니 나중에 화면만 붙이면 된다.

### 값 하나

`VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY` 두 개가 `VITE_NEON_URL` 하나가 됐다.
익명 키가 없다 — 권한은 전적으로 로그인한 사람의 JWT 와 RLS 가 정한다.

### 값을 치른 것

번들이 446 → 605kB (gzip 130 → 167kB) 늘었다. Better Auth 클라이언트와 Supabase
호환 어댑터가 함께 들어온다. 화면 코드를 지키기 위해 낸 값이고, 어댑터를 벗고
Better Auth 를 직접 부르면 되돌릴 수 있다 — 지금은 그럴 이유가 없다.

### 그대로인 것

`supabase/` 디렉터리는 `neon/` 이 됐지만 안의 SQL 은 위 세 가지 말고 그대로다.
검증도 그대로다 — `neon/tests/run.sh` 47가지, `concurrency_test.sh` 5가지가 Neon
모양(`auth.uid()` 가 `request.jwt.claims` 를 읽는 스텁) 위에서 전부 통과한다.


## D15 — 참나무 타건음만 실제 녹음 (확정 · 스택 규칙 예외)

"오디오 에셋 0바이트"는 지금까지 옳았다. 합성이면 파일이 없고, 길이도 크기도
코드로 잰다. 이끼를 녹음으로 바꾸려던 시도(D-없음, 12번 작업)는 원본이 너무
조용해서 잡음만 커졌고, 그래서 접었다.

참나무는 다르다. **나무는 합성으로 나무처럼 들리지 않는다.** 노이즈에 highpass
를 걸고 낮은 해머를 얹으면 "낮은 강철"이 될 뿐, 나무가 울리는 짧은 딱 소리가
안 난다. 그래서 참나무 타건음만 실제 녹음을 쓴다.

### 원본을 어떻게 다뤘나

5.7초짜리 영상에서 타건 18번을 찾아 그중 여섯을 골랐다. 고른 기준은 **크기와
뒤 여유** — 뒤에 130ms 이상 비어 있어야 꼬리에 다음 타건이 안 묻는다.

- 대역: 180Hz 아래와 9kHz 위를 잘랐다. 그 두 곳은 신호 대 잡음이 1dB 남짓,
  즉 전부 잡음이었다. 잘라내니 나머지가 15dB 위로 올라섰다.
- 무게: 2.2kHz 위를 6dB 눕혔다. 자른 그대로는 무게중심이 2242Hz 로 강철(2519)
  에 붙어 D9 가 무너졌다. 눕히니 1961Hz — 원래 합성 참나무가 있던 자리(2033)다.
  **녹음이 참나무 자리를 대신하는 것이지, 팔레트를 옮기는 것이 아니다.**
- 길이 62ms, 꼬리 16ms 는 0으로 재웠다. 남기면 방 소리가 딸려온다.
- 22.05kHz · 16bit 모노. 파일 여섯 개 합쳐 **16.7KB**.

### 재생

- **`decodeAudioData` 를 쓰지 않는다.** 비동기라 키를 누르는 순간과 안 맞는다.
  우리가 만든 WAV 를 직접 뜯어 `createBuffer` 한다 — 동기다.
  (mp3 는 인코더가 앞에 넣는 침묵 50ms 때문에 타건과 어긋난다. 그때 실패한 이유다.)
- 여섯 벌을 **직전과 다른 것으로** 돌려 쓰고, 재생 속도 ±3% · 크기 ±8% 를 흔든다.
  한 벌만 쓰면 두 글자만 쳐도 붙여넣은 소리라는 게 들린다.
- 못 받아오면 **조용히 합성으로 떨어진다**(`fallback`). 오프라인에서도 참나무는
  참나무로 들린다. 검증은 길이로 가른다 — 녹음 62ms, fallback 100ms.
- `.wav` 는 번들에 base64 로 박히지 않게 뺐다(`assetsInlineLimit`). 박으면 PCM 이
  base64 로 부풀고 gzip 도 안 먹어 번들이 16KB 늘었다.

### 나머지 셋은 그대로다

강철(합성 strike) · 설탕(버블) · 이끼(물방울)는 손대지 않았다. 규칙은
"오디오 에셋 0바이트" 가 아니라 **"소리가 그 물건처럼 들려야 한다"** 로 읽는다.
합성으로 되면 합성이고, 안 되면 녹음이다.
